PHASE A · 规划与接入 厘清目标、接入数据、设计本体
①
调研与需求梳理
理解科研学者真实痛点，把模糊诉求拆解为可执行、可度量的业务目标
科研学者痛点访谈 业务目标拆解 成功指标定义
关键交付物：需求调研报告 · 业务蓝图 · 成功指标（KPI）体系
M1 需求与指标基线确认
②
数据接入
通过 Data Connection / Pipeline 将多源异构科研数据接入平台并统一组织
文献源：Zotero · arXiv · Web of Science · CNKI 实验数据 项目与经费 人员组织
关键交付物：数据源清单 · 连接器与数据管道 · 数据字典
③
本体设计
借鉴学术语义标准设计 Ontology 模式，定义对象、关系与消歧策略
复用学术本体词汇：SPAR · BIBO · CiTO 对象类型：学者 · 论文 · 项目 · 实验 · 设备 · 经费 链接类型：作者 · 引用 · 资助 · 产出 实体消歧方案（同名作者 / 机构归一）
关键交付物：本体建模文档（类 / 属性 / 关系）· 命名与消歧规范
M2 本体模型评审通过
PHASE B · 建模与建设 映射抽取、质量约束、构建数字孪生
④
数据映射与抽取
把原始数据按本体模式抽取、清洗并映射为对象 / 属性 / 链接
ETL 数据管道 实体抽取（作者 / 标题 / 引用） 实体消歧与对齐 质检
关键交付物：字段映射规则 · ETL 管道 · 清洗对齐后的数据集
⑤
约束与质量
用形状约束与质量规则保证本体数据可信、可溯源
SHACL 约束校验 数据质量规则 血缘溯源（Lineage）
关键交付物：SHACL 形状 · 数据质量规则集 · 血缘图谱
⑥
语义层建设 · Ontology 数字孪生
构建可操作的语义层，让科研数据「看得见、动得起来」
构建 Ontology 数字孪生（对象 / 链接 / 接口） 动作 Action（如成果认领 · 经费申请）与函数 Function（如 H 指数 · 影响力计算） 权限模型（数据权限 + 操作权限 + 部门 / 密级标记）
关键交付物：Ontology 对象 / 链接 / 接口 · Action / Function · 权限策略
M3 语义层就绪
PHASE C · 应用与上线 构建工具、试点上线、持续运营
⑦
科研工具与应用构建
在语义层之上，为科研学者构建覆盖全生命周期的应用
学术资产管理 检索问答 文献图谱 数据分析看板 智能推荐 科研助手 Agent（AIP）
关键交付物：Workshop 应用 · AIP 问答与 Agent · 可视化看板 · 对外 API
⑧
测试与上线
小范围验证、按标准验收、培训后推向全校
试点（1–2 个课题组） 验收 培训 上线
关键交付物：试点报告 · 验收清单 · 培训材料
M4 正式上线
⑨
运营与迭代
以数据度量效果，持续优化，让知识复合不断复用
效果度量（对标 KPI） 持续优化 知识复合复用
关键交付物：运营看板 · 迭代计划 · 优化清单
端到端闭环：需求 → 数据 → 本体 → 语义 → 应用 → 运营，四个里程碑（M1–M4）逐级把关，最终形成可度量、可持续进化的院校科研数字底座。
